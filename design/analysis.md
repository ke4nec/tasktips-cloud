分析日期：2026-09-19。依据本次工作开始时的工作区源码，包含已有的账号创建、待审核注册和注册设置修改。

- 现有导航：[router.ts](../admin/src/router.ts)、[App.vue](../admin/src/App.vue)。共有 9 个页面路由；用户、项目、设备、诊断、审计共用 `AdminDataView.vue`。
- 实际页面：[OverviewView.vue](../admin/src/views/OverviewView.vue)、[AdminDataView.vue](../admin/src/views/AdminDataView.vue)、[SettingsView.vue](../admin/src/views/SettingsView.vue)、[LoginView.vue](../admin/src/views/LoginView.vue)、[RegisterView.vue](../admin/src/views/RegisterView.vue)。

`system_admin` 的工作是管理账号与运行状态。设计稿只使用账号邮箱、项目名称 / ID、设备名称、计数、状态、时间、错误码和安全审计字段。没有 Todo 标题 / 正文、分类或索引内容、图片内容、content hash、对象存储 key、下载地址或存储凭据。

## 指标口径

1. `AdminOverview.activeUsers`：数据库元数据视图按 `status = active` 统计，表示**已启用账号**。原有「活跃用户」容易被理解为日活，新稿已改名。依据 [0001_init.sql](../migrations/0001_init.sql)。
2. `devices`：是注册设备计数，不能直接标为「在线设备」。设备 `lastSeenAt` 是最近活动时间，也不代表当前在线。
3. `payloadBytes`：显示为「存储用量 / 已引用的内容容量」，单位 GiB；不能推导物理磁盘总量、空闲量或容量占用比例。
4. `queuedRestores`：当前实现包含 `queued` 和 `running`，因此主标签为「待处理恢复」。
5. 时间范围成功率 = 所选日的 `Σsucceeded / Σattempts`；冲突数 = `Σconflicts`。没有请求时应显示「—」，不能把空结果展示为 100%。原型默认有示例数据，空状态单独演示。
6. P50/P99 按日由后端计算，不能取平均后作为 7 / 30 天分位数。新稿显示「最近一日」并附日期；没有 P95 字段，所以不展示 P95。
7. 日趋势使用服务返回的日桶；原型示例为 UTC。当前 SQL `date_trunc('day', created_at)` 的实际边界取决于数据库 session timezone，生产接入应确认服务器统一 UTC，不能仅靠浏览器转换日期就声称已统一。
8. `/health/live` 只证明进程在线。数据库 / 对象存储连接状态必须来自 `/health/ready`；不能由 liveness 推断全部正常。现有 `ApiClient` 已有两个方法，但当前 health store 只调用 liveness；新状态卡需另行接入 readiness。
9. 概览数字是模拟全服务汇总；列表为较小的示例分页集合，不能用当前页条目数反推全局总量。所有列表页显式标注「示例集合」，生产分页按 `hasMore / nextOffset` 实现，不展示不存在的总页数。

## 接口对照与能力差距

以下接口前缀为 `/api/v1/admin`，特别注明的除外。这里只是实现对照，不修改或扩展契约。

| 设计能力                  | 契约 / 源码依据                                             | 接入建议                                                                                 |
| ------------------------- | ----------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 总览指标                  | `GET /overview`                                             | 直接映射现有 8 项，修正显示名称                                                          |
| 曲线、成功率、每日统计    | `GET /metrics/trends?days=`                                 | 使用现有按日字段，保持 1 / 7 / 30 天选择                                                 |
| 服务连接状态              | `/health/live`、`/health/ready`                             | 保留检查中 / 不可用；不输出连接参数                                                      |
| 用户列表 / 新建           | `GET/POST /users`                                           | DTO 继续使用 OpenAPI 生成类型                                                            |
| 批准 / 启用 / 禁用        | `POST /users/{userId}/enable`、`disable`                    | 原因发送后端；目标 ID 对照是客户端确认步骤，不改请求体                                   |
| 用户关联资源              | `GET /users/{userId}/projects`、`devices`                   | 生产应调用专用接口；原型用当前示例集合过滤演示                                           |
| 项目名称 / ID 搜索        | `GET /projects?search=`                                     | 契约支持远程搜索；加防抖与过期请求保护                                                   |
| 项目历史元数据            | `GET /projects/{projectId}/history-metadata`                | 接口已有，现有页面尚未消费；按 allowlist 展示版本和墓碑标志                              |
| 两种恢复目标              | `POST /projects/{projectId}/restores` 的 `RestoreRequest`   | 已有 `snapshotId` / `targetChangeSequence` 二选一；两步确认是呈现改进                    |
| 快照选择                  | 管理契约未提供快照列表                                      | 原型只提供输入已有快照 ID，不虚构可浏览的管理员快照目录                                  |
| 任务跟踪                  | `GET /operations`                                           | 继续轮询；展示状态、尝试次数、下次运行、取消标志和错误码，不虚构百分比                   |
| 设备活动时间              | `GET /devices` 的 `lastSeenAt / lastPullAt / lastPushAt`    | 已有字段可加入详情；未返回时显示「—」                                                    |
| 审计列表 / CSV            | `GET /audit-events`、`/audit-events.csv`                    | 生产导出使用同源鉴权端点；原型只生成示例 CSV                                             |
| 注册设置                  | `GET/PUT /settings/registration`                            | 确认后保存；正式接入需保存中禁用、失败回滚                                               |
| 注册                      | `/api/v1/auth/registration-status`、`/api/v1/auth/register` | 保留关闭、成功、待审核、校验与错误状态                                                   |
| 主题                      | 新增浏览器本地偏好                                          | 无需 API 字段；浅色 / 深色 / 跟随系统                                                    |
| 表格状态筛选 / 非项目搜索 | 大多数列表只有 limit / offset                               | 原型注明「筛选当前页」；全服务筛选需要先补契约与服务端实现，不能把前端过滤宣称为全局搜索 |

## 未假装已经实现的能力

- **邀请管理**：契约已有邀请列表、创建、撤销、重发接口；当前 admin 页面没有相应入口。后续可在用户页增加「邀请」标签，需单独设计邀请生命周期与令牌安全展示。
- **管理员撤销设备**：当前设备撤销端点属于用户作用域，管理契约没有专用撤销路由。设计稿只展示撤销状态，不将管理 token 发往用户端点。需要明确授权与契约后才能添加按钮。
- **恢复取消 / 失败后重新开放同步**：client 中存在用户路径的取消方法，不能据此认定管理端已有取消权限。`restore-reopen` 管理接口虽已存在，但必须先有完整性校验与审计原因流程，不应给普通错误面板放一个直接「恢复服务」按钮。
- **永久清除账号 / 最终导出**：契约、客户端包含清除与重新认证能力，当前页面未暴露。独立流程必须包含密码重新认证、nonce、目标确认、原因、异步状态；管理员不能获得用户内容导出下载入口。此稿没有把该能力混入常用操作。
- **错误码聚合、P95、worker 队列总量、项目容量 / 对象总数**：架构蓝图有方向，但现有管理 DTO 没有全部数据，原型不虚构相应 API 字段。
- **语言切换**：生产已有中英文资源结构；设计稿的静态布局只验证简体中文，未宣称完成英文界面验收。文案仍通过 vue-i18n key 输出，方便后续迁移。

## 落地优先级

第一批：替换应用壳层与主题令牌，统一表格、状态标签、详情抽屉和用户操作确认；保留已存在的权限与数据请求链路。

第二批：接入现有趋势、历史元数据、审计 CSV 和设备活动字段；完成恢复两步确认、提交锁定、错误反馈与任务跟踪。以现有契约的字段为准，不复制原型中的示例视图模型作为 DTO。

第三批：在明确需求后补齐邀请、管理员设备撤销、清除和恢复失败处置流程。涉及新增 / 变化行为时，同步维护架构基线与 `contracts/openapi.yaml`。
