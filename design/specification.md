# UI 设计与交互规范

## 设计方向

这是 TaskTips 的管理工具，视觉重点是安静、清晰、可判断。保留桌面客户端的灰色工作区、白色 / 深灰面板、Fluent 蓝色强调和左侧短竖线选中态；蓝色只用于当前入口、主要操作和数据强调。

主结构为侧栏、轻量顶部路径与内容区。左侧按「工作空间 / 服务运维」组织已有功能，底部固定设置与管理员身份。取消旧版深色横栏与白色侧栏在浅色模式下的强烈割裂。

## 颜色来源

`client-theme.css` 是桌面客户端主题文件的本地副本，保留其语义变量；正式实现宜复制需要的令牌或维护可追溯的共享源，不应在构建时跨仓库引用路径。

| 语义                      | 浅色      | 深色      | 用途                   |
| ------------------------- | --------- | --------- | ---------------------- |
| 工作区 `--bg`             | `#F3F3F3` | `#202020` | 应用背景、侧栏         |
| 面板 `--surface`          | `#FFFFFF` | `#2B2B2B` | 表格、指标、弹层       |
| 主文字 `--text`           | `#1B1B1B` | `#FFFFFF` | 标题、重要数字         |
| 次文字 `--text-secondary` | `#5F5F5F` | `#B4B4B4` | 字段、说明、导航       |
| 主色 `--accent`           | `#0078D4` | `#4A9EFF` | 主要操作、曲线、选中态 |
| 正常 `--ok`               | `#0F7B0F` | `#6CCB5F` | 成功 / 正常状态        |
| 危险 `--danger`           | `#C42B1C` | `#FF6B5E` | 失败、禁用确认         |
| 描边 `--border`           | 黑色 10%  | 白色 9%   | 1px 分隔线             |

后台扩展：提醒色浅色 `#8A5700`、深色 `#EFBE65`；浅色辅助文案使用 `#737373`，降低小字号的阅读负担。深色主按钮文字使用深蓝 `#10243B`，保证亮蓝背景上的可读性。便签颜色不用于整块后台背景，只在合成账号头像上少量辅助区分。

## 排版与尺寸

- 字体：Segoe UI Variable / Segoe UI / Microsoft YaHei / Noto Sans CJK SC / sans-serif；没有远程字体。
- 页面标题 28px / 600；模块标题 16px / 600；正文 13px；表格主信息 12px；说明 10–12px。生产环境应按目标平台检查系统字体与缩放后的可读性，必要时增大辅助字号。
- 计数使用等宽数字；ID、版本和请求码使用 Cascadia Code / Consolas 等宽字体。主表显示短 ID，抽屉保留完整 ID；危险确认始终要求完整 ID。
- 侧栏 224px；顶部路径 60px；主区内边距 32px；主区最大宽度 1620px。
- 面板圆角 8px、控件 5px、弹窗 10px；弹层使用客户端阴影，普通面板只保留轻微边框和阴影。
- 列表主行至少 54px，表头 39px；普通按钮高 34px；登录输入与按钮约 39px。
- 普通表格按列设置宽度和对齐，不再对所有字段统一最小 150px。长表格在自身容器中横向滚动，不撑开页面。

## 页面信息层级

**总览**：用户 / 项目 / 设备 / 存储四项主要指标；已启用账号 / 历史版本 / 删除标记 / 待处理恢复四项次级指标；同步趋势 + 服务连接状态；最近操作。每个状态有文字，不仅依赖颜色。

**用户**：邮箱作为识别入口，短 ID 放在次行；状态标签与动作相邻。待审核账号突出「批准」，已启用普通账号提供「禁用」，管理员行只提供详情，避免设计稿暗示可以随意禁用自身。待审核页签计数是本页 / 示例集合范围，不代表后端未提供的全局待审核总数。

**项目**：项目名 + 短 ID 为入口；状态、代际、变更序号可同时扫描。详情抽屉显示完整元数据和最近历史；时间线只包含版本、设备标识和墓碑含义，不展示内容。

**同步诊断**：同步列表不强制展示恢复特有字段。任务详情按操作类型显示尝试次数、下次执行、取消请求和错误码；不存在的值显示「—」。执行中只展示状态，不生成没有后端依据的进度百分比。

**审计**：中文行为名与原始事件码并列，保留调试与审计精确性。只映射认可的安全 metadata 字段，不渲染任意 JSON 响应。原型的 `reason` 是展示层示例，正式实现需从后端 allowlist 的安全字段提取。

**登录 / 注册**：左侧使用本地 SVG / CSS 连接示意与客户端图标，右侧表单。明确管理员登录与普通用户申请账号的区别。页面不收集、记录或发送任何真实凭据。

## 关键流程

### 审核与禁用

1. 从账号行进入确认弹窗，展示邮箱和完整用户 ID。
2. 批准 / 启用填写原因；禁用额外输入完整用户 ID。
3. 提交中锁定表单，防止重复操作；失败保留输入并提示可理解的错误，允许重试。原型演示本地立即完成，不模拟网络延迟。
4. 成功后刷新当前页及状态，写入审计。若正在看待审核页签，已批准账号从当前结果中消失。

### 代发起恢复

1. 项目列表 → 项目详情，确认 ID、状态、generation 与 change sequence。
2. 第一步：选择目标变更序号，或输入已知快照 UUID；填写原因。两种目标不可同时提交。
3. 第二步：说明维护窗口、恢复前快照、新版本与新 generation 的影响；再次展示目标；要求输入完整项目 ID。
4. 提交只代表任务进入队列。跳转同步诊断的恢复任务页签，展示 queued / running / succeeded / failed / cancelled。
5. 失败时保留任务 ID、安全错误码与计数；若项目仍 maintenance，必须经过引用完整性校验和授权流程，不能自动假定恢复可安全重试或项目可重新开放。

非 active 项目的恢复按钮在此设计中禁用。最终允许状态必须依据服务端业务规则，不能仅凭原型控件代替授权与状态校验。

### 注册设置

切换时确认影响；保存成功再更新最终状态，失败应回滚至服务端真实值。关闭注册仅影响新申请，已有账号不受影响。注册表单保留密码至少 12 位且包含字母 / 数字、确认密码一致的当前规则。

## 状态与可访问性

- 加载：结构化骨架、`aria-busy`，避免暂时展示 0。
- 初始空数据：说明记录将何时出现；筛选无结果：提供重置入口。正式产品应根据页面区分文案。
- 加载失败：保留请求 ID 和重试入口；不展示内部路径、SQL、凭据或原始响应正文。
- 状态名称全部中文化，图标与文字共同表达；保留必要原始错误码。
- 表单有可关联的 label，图标按钮有 `aria-label`，键盘焦点使用蓝色描边。
- 弹窗使用原生 `dialog.showModal()`，支持焦点约束、Escape 关闭与关闭后焦点返回；点击背景可关闭，真实落地时对未提交输入可增加丢弃提示。
- 明暗主题可手动切换或跟随系统；尊重 `prefers-reduced-motion`。原型主要依靠布局和状态变化，不引入装饰性动画。
- 目前浏览器检查包含按钮名称与布局，不等同于完整的 WCAG、屏幕阅读器或色觉验收。

## 响应式

- 1440px / 1280px 为主要管理窗口，截图均覆盖明暗两套主题。
- 1200px 以下收紧侧栏与内边距；较窄宽度下图表和连接状态纵向排列。
- 760px 以下侧栏缩为图标轨道，保留可访问名称；指标改为两列，工具栏换行。
- 390px 验证页面无整体横向溢出；长表格在内部滚动，详情抽屉填满可用宽度。管理端以桌面使用为主，手机宽度用于保证可访问与故障排查可用。

## 正式接入时必须保留的约束

- 所有正式 API 类型来自 OpenAPI 生成客户端，不能把原型的合成视图记录复制为手写 DTO。
- 可见文案通过 vue-i18n key 输出；将设计稿新增键迁移到生产中英文资源并验证长文案。
- 路由权限、会话恢复、access token 内存态、HttpOnly cookie、同源与 CSRF 防护保持现有架构。
- 正式调用只访问授权的元数据管理接口；不添加用户 payload handler、对象存储链接或存储设置表单。
- 列表轮询避免覆盖未提交表单；页面隐藏时暂停，离开页面后清理 timer，保护过期请求结果。
- 审计 CSV 正式接入使用已鉴权接口并保持安全字段集合；浏览器生成 CSV 仅属于此离线演示。
- 本次输出是设计提案，不是生产能力变更；若落地涉及行为 / 契约变化，再同步更新架构文档与 OpenAPI。
